## Source findings

1. The helper's `FileSnapshot` records dev/inode/mode/uid/gid/size/atime_ns/mtime_ns/ctime_ns. `classify_inotify_event` reports all content masks as `E 1` and any `IN_ATTRIB` as `E 2`; only an exact `IN_ACCESS` reaches snapshot classification. For that access, identity/type change raises `WatchError`, size or mtime change reports `E 1`, other sampled metadata change reports `E 2`, and an identical tuple is suppressed. This preserves the v1 protocol and the existing conservative handling of real updates (`server/scpfs_watch.py`, `FileSnapshot`, `classify_access_snapshot`, `classify_inotify_event`).
2. `Watcher.ensure` keeps one sample per inotify watch descriptor and retains the previous sample when a hard-link alias receives the same descriptor. It compares stat before and after installing a new watch, so a timestamp or identity change during installation fails closed rather than entering the cache with an unproven baseline. `_verified_file_snapshot` verifies every ancestor without following symlinks or crossing the recorded device, then accepts only a recorded alias whose leaf still identifies the watched inode; no valid alias or disagreeing alias samples raises `WatchError`. `drain_events` treats queue overflow, watch loss and unknown descriptors as fatal, and updates a file's sample after a classified event (`server/scpfs_watch.py`, `ensure`, `_verified_file_snapshot`, `drain_events`).
3. The existing `W` flow drains events, revalidates coverage and then acknowledges; `B` drains before acknowledgement. A deleted hard-link alias may be skipped when another recorded alias still identifies the same inode. That does not by itself accept stale namespace data: the watched parent supplies the delete/rename content event, and a later `W` for the replaced path fails its identity check. The helper regression fixture explicitly exercises this ownership case. If a new test finds a namespace event can be lost across the barrier, this exception must be revisited before release.
4. Cold payload admission now requires both unchanged content provenance and exact atime equality between the backend's post-restore stat and the verification stat, after a stable barrier/generation (`src/scpfs.c`, `scpfs_cache_stat_provenance_mismatch_mask`, cold `same_stat` branch). Thus a byte copy is not published under a new metadata epoch with the prior atime. The warm metadata-stale path still takes a fresh stat, a verification barrier and byte-provenance check; `scp_cache_validate_payload` then replaces its saved provenance with that fresh stat. Its byte comparator still excludes atime while checking type/dev/inode/size/mtime/mode/uid/gid/ctime (`src/scpfs.c`, warm `scp_cache_validate_payload` branch; `src/scp_cache.c`, `scp_cache_same_payload_provenance`). The backend conflict comparator remains outside this change.

## Cold-atime race gate

The new cold admission condition is explicit: after a stable monitor generation, a payload is published only if every byte-provenance field **and** `handle->current.atime_ns == fresh_stat.atime_ns` holds (`src/scpfs.c:1574-1583`). The isolated `cold_atime_mismatch` counter can increment only when an atime change lands between the backend's final post-restore stat and the first post-download barrier, so that `after` already includes its `E 2` but the subsequent verification stat sees the new atime. If the change lands later, the second barrier rejects the generation first. Real atime advances are therefore usually expected to exercise the metadata-generation rejection, not that narrow counter.

**Architecture acceptance decision:** a deterministic adapter fixture forced into that particular timing window is not required for this bounded repair. The direct source predicate, real helper tests for changed atime and ctime-mediated `B -> A` restoration, the warm-atime unit regression, actual Debug/Release cache pressure, and now the V:/R: host checks satisfy this focused gate. No saved run hit the isolated `cold_atime_mismatch` (bit 9) branch; do not report it as runtime-covered. A bounded owned-file experiment could still try to hit it without changing notifications or injecting stale data, but a zero-hit result would not undo the observed generation rejection or source predicate. This acceptance is narrower than a deterministic race proof and does not establish linearizable timestamp snapshots.

If a later failure makes direct deterministic coverage necessary, the smallest internal design is a private cold-admission predicate taking both stat snapshots and generation states, used by the adapter and a focused unit fixture. Keep that seam internal; do not add a public monitor protocol, disable event reporting, or inject stale production data merely to reach the counter.

## Remaining boundary

This review accepts the repair for the measured root `/` workload and the existing fixture matrix. Production-host V: and R: checks were read-only; external mutation and timestamp visibility were exercised in owned WSL/WinFsp fixtures, not by changing host system files. The observed 11-byte warm-read timings are not an all-file-size throughput or latency guarantee. Strictatime/noatime mount-mode combinations, prolonged service operation and a Windows reboot were not tested. The root task's saved verification establishes build, publication and runtime behavior; this focused architecture review does not replace those checks or extend them to a whole-filesystem audit.
