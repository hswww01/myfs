# SCPFS cache: file-access event decision

Date: 2026-10-03 (Asia/Shanghai). Scope: the root `/` cache regression on the production host and the bounded source change described below. This is an architecture decision and implementation gate, not an acceptance claim.

## Objective and confirmed behavior

The remote helper adds `IN_ACCESS` to every watched regular file (`server/scpfs_watch.py:151-160`). Its drain currently sends `E 2` for every access event without checking whether any cached metadata changed (`server/scpfs_watch.py:172-191`). The client advances one global metadata generation for `E 2` (`src/scp_watch.c:211-228`); the adapter then invalidates all cached stat and directory-list entries (`src/scpfs.c:610-648`). A root `/` listing watches ordinary system files, so SSH's unrelated reads of `/etc/group`, `/etc/passwd`, `/etc/login.defs`, and `/etc/bash.bashrc` repeatedly invalidate metadata needed to reuse an unchanged file's payload.

The bounded production observer in `build/cache-access-trace/23637e4eeac3da05/result.json` watched 106 `/etc` regular files during six R: reads. It recorded hundreds of `IN_ACCESS` events on those unrelated files and no modify or attribute events. Read times were 858-2098 ms in that observation. This establishes the event source and the performance failure in that run, not a complete correctness proof. The earlier isolated V: result in `build/cache-live-diagnose/f0de69da08521fe3/result.json` showed 840-1032 ms reads after `/etc` listing with the original payload still present.

Linux defines `IN_ACCESS` as file access, including `read(2)` and `execve(2)`; the event does not assert a timestamp change. `IN_ATTRIB` covers metadata updates, including timestamp changes. An explicit `utimensat(2)` also updates ctime even when the requested atime and mtime end at their previous values. References: [inotify(7)](https://man7.org/linux/man-pages/man7/inotify.7.html) and [utimensat(2)](https://man7.org/linux/man-pages/man2/utimensat.2.html). The project's actual helper fixture has observed `IN_ACCESS` for file reads and `E 2` for `touch -c -a`.

## Decision

Keep protocol v1, the global generations, acknowledged watches and barriers, and the existing cache capacity and fail-closed policy. Filter **only pure `IN_ACCESS` events for watched regular-file inodes** in the Linux helper. Suppress `E 2` only when a new `lstat` sample proves the watched inode's relevant metadata has not changed since that watch descriptor's last verified sample. Compare at least device, inode, file type/mode, uid, gid, size, atime in nanoseconds, mtime in nanoseconds, and ctime in nanoseconds. Preserve one sample per watch descriptor, not per path: inotify reports events by inode and hard-link aliases can return the same watch descriptor. Adding or ensuring another alias must not reset the existing sample or consume an event pending on that inode.

An actual atime or ctime change emits `E 2` and advances the verified sample. A size or mtime change seen while processing an access event should conservatively emit the content event `E 1`; an identity change, missing/replaced path, unsupported object, unavailable sample, or ambiguous watch-descriptor mapping fails the monitor closed. A pure access event with an unchanged sample emits nothing. Any event containing `IN_ATTRIB` still emits `E 2` unconditionally, because metadata outside the sampled fields can change. `IN_MODIFY`, `IN_CLOSE_WRITE`, namespace events and watch-loss/overflow behavior retain their existing content-generation or fail-closed handling. Refresh the per-descriptor sample after a reported file event so subsequent unchanged reads do not generate duplicate metadata events. The helper must not read file content or modify remote timestamps to make this decision.

The file path used for `lstat` must still resolve to that descriptor's recorded inode, with no symlink following. The existing watch limit of 4096, canonical root check, revalidated `W` acknowledgement, barrier ordering and reconnection invalidation remain mandatory. If no safe path exists for a hard-linked inode, mark monitoring unhealthy rather than guessing that an access was harmless.

Add an **atime equality check only to cold payload admission's final-stat comparison** in `src/scpfs.c`. Today its comparison excludes atime (`scpfs_cache_stat_provenance_mismatch_mask`, `src/scpfs.c:650-664`), so an atime change before the final verification stat can publish a payload at the new metadata epoch while retaining the old atime in the cached stat (`src/scpfs.c:1547-1585`). On this mismatch, return the fetched bytes without publishing that stale metadata/payload pair; a later open can retry. Keep atime excluded from the byte-provenance comparator in `src/scp_cache.c:478-505`: after a genuine metadata event, a fresh stat and stable barrier may retain immutable bytes when type, device, inode, size, mtime, mode, uid, gid and ctime still match, while replacing the cached stat with the fresh atime. Do not change the backend's mutation-conflict comparator merely to implement this cache repair.

This is the smallest repair that addresses the observed reads and preserves timestamp visibility. A path-scoped event protocol would change the wire format, monitor API, dependency bookkeeping for directory listings and hard links, and the race proof. Defer it unless measured results show the bounded v1 repair cannot meet the root `/` workload. Blindly dropping `IN_ACCESS` is rejected because a real read can advance atime, and the mounted metadata must reflect that change.

## Required implementation and validation gates

1. Prove on a real inotify fixture that repeated reads with unchanged atime/ctime produce no `E 2`; a read that advances atime and an explicit atime-only timestamp update do produce metadata invalidation. Include an atime `B -> A` restore before a barrier and verify ctime prevents suppressing the change. Confirm `IN_ATTRIB` remains unconditional even when the sampled tuple appears equal.
2. Cover two hard-link paths sharing one watch descriptor, one alias being removed or replaced, a watch identity change during sampling/acknowledgement, `IN_Q_OVERFLOW`, `IN_IGNORED`, and stat failure. These must invalidate or fail closed according to the existing rules; no old inode can be acknowledged for a replacement path.
3. Verify the cold-admission source predicate rejects a differing atime between the download's post-restore stat and final stat after a stable generation. A deterministic runtime hit of that narrow race branch is not required for the bounded repair if real atime-change notifications, metadata-generation rejection, warm atime revalidation and the final mount gates pass; record that limit explicitly. Cover warm metadata-stale revalidation: unchanged byte provenance retains payload bytes and returns the fresh atime; changed provenance evicts them.
4. Re-run the actual WinFsp file fixture with frequent unrelated watched-file reads during cold and warm reads of file A, counting helper events, barriers, stat/list calls and payload hits. Verify warm A reads return to the local-copy path and genuine external atime, mode, content and rename changes still become visible. The production-host temporary mount on an unused drive and R: behavior must be reported separately; do not disturb the running R: service during development.
5. Run the project's clang-cl/vcpkg Debug and Release suites and static-import/runtime-module checks for a candidate. A focused fixture pass is not proof of production acceptance; compare the final packaged executable's hash and repeat the bounded root `/` measurement before claiming the regression fixed.

## Limits and handoff

An access-event snapshot is a conservative, event-driven cache invalidation method. It relies on supported local Linux filesystems, available inotify events, verified inode identity, and detectable timestamp/provenance changes; it is not a linearizable filesystem snapshot. Where those assumptions fail, the monitor must invalidate/bypass caching instead of serving an unverified entry. No strictatime/noatime mount-mode matrix or post-fix production timing has been run for this decision.

Implementation belongs in the helper's watch-descriptor bookkeeping and the adapter's cold admission check. The Windows monitor protocol parser, backend timestamp restoration, conflict rules, frontend, service state and unrelated files are outside this repair. The next worker should implement these bounds, run the gates above, and return any unresolved identity or event-ordering issue for another architecture decision before widening the protocol.
